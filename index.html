0开始前检查（3 分钟）

Render 只是“把你的代码放到公网运行”，它本身不存数据。所以先确认这 3 样都齐了：

  • GitHub 仓库已存在，里面是你的 API 代码（本 Lab 用 CSIS3380-Module8-Simple-Rest-API-Exercise-Lab-Submission，根目录只有 userlist-api-jinran/）。
  • MongoDB Atlas 集群是 Active，Network Access 已放行 0.0.0.0/0（Render 出口 IP 不固定）。
  • Atlas 数据库用户密码是有效的——如果之前泄露过，先去 Atlas → Database Access 重置，再用新密码拼连接串。
密码安全：连接串 mongodb+srv://用户:密码@cluster…/UserList?... 里的密码只放在 Render 的 Environment Variables 里，绝对不要写进 GitHub 代码或 .env.example。仓库里的 .gitignore 必须排除 .env。
✅ 过关：上面 3 项都 confirmed，且你已登录 render.com。

3-1 Advanced（高级设置）逐项处理

你截图里 Configure 页底部有 Advanced，展开后是一堆选项。对本 Lab 全部保持默认即可，只有 Health Check Path 一项要注意：

Advanced 里的项目你要做的原因
Secret Files（Add Secret File）❌ 不用碰我们用上面的 Environment Variables 存连接串，不用 Secret File
Health Check Path（显示 /healthz）⚠️ 确保这个框最终为空见下方“怎么判断”
Pre-Deploy Command❌ 留空不需要数据库迁移等预部署操作
Auto-Deploy（On Commit）✅ 保持默认 On Commit以后你 push 新 commit 会自动重新部署，省事
Build Filters（Included / Ignored Paths）❌ 全部留空不用按路径过滤自动部署
Health Check Path 的坑 + 怎么判断：你看到的 /healthz 很可能是灰色占位文字（placeholder），只是告诉你“填的话填这种格式”，输入框其实是空的。
判断方法：用鼠标点一下那个输入框——
· 点进去后文字是浅灰 / 一打字就消失 → 占位符，留空就好；
· 点进去后 /healthz 是深色真实文字 → 全选删掉，让它空着。
为什么必须空：我们的 API 没有 /healthz 路由。若 Render 真去检查它，会一直得到 404，可能把服务标记成 unhealthy 或反复重启。最稳妥：不管原来是什么，确保这个框最后为空。
✅ 过关：Name / Root Directory / Build Command / Start Command 四项都改完；Advanced 里 Health Check Path 确认为空，其余默认。

4环境变量 MONGODB_URI

找到 Environment Variables 区域（有的版本在 Configure 页底部，有的在创建服务后的 Environment 标签页）。点 Add Environment Variable，加一条：

KeyValue
MONGODB_URImongodb+srv://用户名:新密码@cluster1.6qa39ly.mongodb.net/UserList?retryWrites=true&w=majority
连接串模板（把占位符换成你自己的）
mongodb+srv://USER:PASSWORD@CLUSTER.mongodb.net/UserList?retryWrites=true&w=majority
  • USER / PASSWORD：Atlas 数据库用户的用户名和你重置后的新密码。
  • CLUSTER：Atlas 给你的集群地址（Connect → Drivers 里复制）。
  • /UserList 不能少——这是题目要求的数据库名，漏了数据会写进默认库。
  • PORT 不用填，Render 会自动提供，代码里的 process.env.PORT || 3000 会自动用它。
环境变量 ≠ 代码：连接串只放这里，不要提交到 GitHub。Render 会把这个值注入到运行时的 process.env.MONGODB_URI，代码第 1 行 require('dotenv').config() 在本地读 .env，在 Render 上则直接用环境变量，两边代码完全一样。
✅ 过关：Environment 里能看到 MONGODB_URI 这一条。

5Deploy + 验证上线成功

5-1 部署

点页面最底部的紫色按钮 Deploy web service（有些 Render 版本叫 Create Web Service，是同一个按钮，位置一样在最下面，旁边显示 $0 / month）。页面跳到服务详情页，状态显示 Deploying...，等 1–3 分钟变成绿色的 Live。

5-2 拿链接

页面顶部会出现你的公网网址，形如：

部署链接示例
https://userlist-api-jinran.onrender.com

5-3 验证（两个都要成功）

  1. 浏览器打开 https://你的服务.onrender.com/ → 应看到：
    期望响应
    {"message":"Welcome to the UserList API"}
  2. 再打开 https://你的服务.onrender.com/api/users → 应看到 [] 或用户数组。能返回 JSON 就说明 Express 正常、Atlas 也连上了。
  3. （可选）用 Postman 对部署地址做一次 POST /api/users/newuser，body {"id":9,"email":"test@a.com","username":"jinran"}，应返回 201。
免费实例会休眠：闲置一段时间后，第一个请求可能要等约 1 分钟才响应，这是正常的，不是挂了。老师第一次打开也可能遇到，属正常现象。
✅ 过关：两个网址都能看到 JSON，Postman 能完成一次 POST。
